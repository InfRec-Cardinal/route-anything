# X13_memory -- router memory replayed on recorded outcomes with real verifiers

Generated by `run.py` (seed 20260917); runtime 648.6 s; 50 streams x 60000 rounds, late window 10000 rounds; 1000 bootstrap resamples (paired over streams; task-cluster resampling as a second decision rule).

## What this experiment is (and is not)

Proposition thm:memory, eq:noise-threshold, prop:cascade-records, eq:ttl / eq:fifo and Remark rem:state-dependent-writes are tested on an ACRouter-style record store REPLAYED over the recorded CodeRouterBench outcomes. **No ACRouter run logs exist in the released package** (`outputs_hf/outputs/current/id_decisions.jsonl` holds one chosen model per task and no memory writes, verifier sub-signals or kNN neighbours), so the memory writes are generated here: the verifier is run on the RECORDED responses (`response_matrix.json`) and the record process is simulated. Everything that is an outcome (score, cost, latency, response text, sandbox verdict) is real; the arrival order, the exploration coin, the expiration coins and the retention rule are constructed. Evidence kind: SEMI-SYNTHETIC with OUT-OF-SAMPLE primitives (probing) unless marked otherwise.

## Setup

- Data: `$ACROUTER_DATA/coderouterbench/id_results_long.csv` (scores, `cost_usd`, latency), `matrices/phase1_acrouter_v2/response_matrix.json` (recorded responses); prompts / tests via `common/sources.py`; verifiers via `common/sandbox.py`.
- Replay population: id_test tasks with an execution-based verifier: sources humaneval, he (completion), mbpp, bcb, cruxeval, hex (python), lcb, ds1000; test-generation prompts excluded; **all-zero bcb / lcb / ds1000 tasks excluded as UNGRADED** (released grader failure, Addendum 2) -> 867 tasks in 12 dimension x source cells (the 9 other cells have no local verifier). Probing counterpart: 2044 tasks (primitives are fitted there only).
- 21-cell population (oracle W0 and the syntax-only W1): all id_test tasks minus the all-zero bcb / lcb / ds1000 tasks -> 2432 tasks (probing 5890); sensitivity `c21all` keeps every task (2919). EXEC-CLEAN robustness pool `c9`: the 12-cell population restricted to humaneval / he / mbpp / hex / bcb -> 334 tasks in 9 cells (probing 704). Populations suffixed `o` use always-Opus as the uninformed action instead of DimensionBest.
- Empty recorded responses (data gap in response_matrix.json; 401 of 6936 pairs in the replay population, 216 of them with released score 1) are unverifiable: every verifier is imputed the released truth on them (Addendum 2); they are excluded from the verifier operating-point table.
- Cluster store (proxy for ACRouter's embedding-kNN memory; **no embedding model is available here**): TF-IDF (1-2 grams, 20000 features) + MiniBatchKMeans k=50 fitted on the probing prompts, id_test prompts assigned to the nearest centroid.
- Prior (uninformed action, ACRouter's DimensionBest warm start) fitted on probing: algorithm: qwen3.5-plus, bug_fixing: claude-opus-4-6, code_completion: claude-opus-4-6, code_generation: claude-opus-4-6, code_refactoring: gpt-5.4, code_understanding: kimi-k2.5, data_science: kimi-k2.5, multi_language: claude-opus-4-6, test_generation: Qwen3-Max.
- Stream: each of 50 streams draws 60000 tasks i.i.d. with replacement from the population (the independent arrivals of sec:memory; nu_j = the population's cell frequencies); the store starts empty; stationary statistics use the last 10000 rounds; the finite-horizon identity is also checked on ONE random pass over the population (TRANS pool).
- Writer / record process. Fixed process (FP, the hypothesis of thm:memory): with probability eps = 0.25 a round explores a uniformly random model for BOTH routers and the verifier's accept writes (model) to the arriving cell; a write is INFORMATIVE if the model is truly correct (released score >= 1) and ERRONEOUS if the verifier accepted an incorrect output. State-dependent (SD, ACRouter-like): every round the informed router fields the record model (prior if uncovered; epsilon-greedy 0.05), verifies and writes if accepted. Informed action = model of the cell's newest valid record; uninformed = prior. Retention: geometric expiration delta in [0.0, 0.01], TTL E in [50, 200, 1000], event FIFO M in [50, 200, 1000, 5000], LRU over distinct cells (capacity ceil(J/3), ceil(2J/3)).
- Verifiers (all on recorded responses): W0 oracle = released score >= 1; W1 = ACRouter's tools: the prompt's doctest examples (public cases for lcb) run in the sandbox, a syntax check when the prompt shows no example (mbpp descriptions, cruxeval, ds1000), non-empty text for non-python tasks; W2 = hidden-test sandbox (`sandbox.verify_response`; lcb capped at 25 cases; empty recorded responses with released score 1 are unverifiable and imputed from the released score); W3 = LLM judge deepseek-v4-pro (thinking off) on a 300-task id_test subsample and 15 probing tasks per cell.
- W3 status: X8's 60-item calibration table (`X8_operating_point/cache/calibration.json`) gives AUROC dsv4pro_think 0.658 [0.519, 0.781], dsv4pro_nothink 0.656 [0.520, 0.777], dsflash 0.734 [0.605, 0.843], qwen3max 0.583 [0.448, 0.709], grok46 0.842 [0.727, 0.935]. W3 = deepseek-v4-pro (thinking off; AUROC 0.656 in X8's table, below the protocol's 0.75 gate) was run on the 300-task subsample per the coordinator's first instruction and is reported as the NOISY-WRITER case, not as a trustworthy verifier; own check on its 3670 judged (task, model) pairs: AUROC 0.763, accuracy 0.720; error rows 0. W3g = grok-4.6 (X8's best judge, AUROC 0.842; ~3,126 tokens and ~30-130 s per call) could not be run on the full subsample: at the uncalibrated ledger rate a call costs ~150-230 units, so the 300-task W3 would need ~0.6M ledger units, twice the shared cap. It was run as a budget-capped PILOT on 12 id_test + 6 probing tasks of the cells ['code_generation|mbpp', 'code_completion|mbpp'] drawn from the deepseek subsample (same pairs for both judges): 144 calls, 12318 ledger units, cap reached: False; error rows in cache: 0; own check AUROC 0.596 (accuracy 0.486) on 148 pairs vs deepseek 0.387 on the same pairs.
- API spend (tag X13, shared ledger): 3586 live calls, 2,969,818 prompt + 479,760 completion tokens, 14188.0 ledger units; by model: deepseek-v4-pro 3458 live calls, 2,962,826 tokens, 966.0 units; grok-4.6 128 live calls, 486,752 tokens, 13222.1 units (deepseek-v4-pro at the calibrated 0.00034 units/token, grok-4.6 at the default 0.05). No other API use.
- Cost basis: dollars (csv `cost_usd`) unless a row says seconds (latency + verifier wall-clock).

## Hypothesis violations measured

- g^I > 0 > g^W (eq:noise-threshold's premise) holds in 54/1014 cell rows (sign patterns of (g^I, g^W): {'undefined': 470, 'I-W-': 200, 'I+W+': 242, 'I+W-': 66, 'I-W+': 36}; 'undefined' = no accepted-and-correct or no accepted-and-incorrect write of any model in the probing cell). A record is a model name, and the eight models differ up to 20x in price, so in dollars both record types usually move value and cost in the same direction: relative to an Opus prior any record points to a cheaper model (both g > 0), relative to a cheap prior (algorithm: qwen3.5-plus, data_science: kimi-k2.5) to a dearer one (both g < 0). The general per-cell sign rule sign(omega g^I + psi g^W) does not need the premise (agreement 0.944 on 909 decided cells).

## Deviations from the protocol and limitations

- ACRouter's real Memory logs (采集 A) do not exist; the memory is replayed on recorded outcomes with our verifiers, so the results test the record theory on an ACRouter-STYLE store, not the released system. Records carry (model) only; rejected attempts write nothing (no negative records).
- Only 12 of the 21 dimension x source cells have an execution-based verifier; the 21-cell rows use the oracle (released score) or the syntax-only / non-empty W1 rule, whose truth for the Proxy+ dimensions is the released judge score.
- All-zero bcb / lcb / ds1000 tasks (released grader failure, Addendum 2) are excluded from every cell estimate; the sensitivity rows `c21all` (all 2,919 id_test tasks, oracle W0) give delta 0.0: predicted -0.1119, realized d_eta -22.304 [-23.396, -21.100]; delta 0.01: predicted -0.0655, realized d_eta -11.923 [-12.594, -11.228] (same signs as the excluded-task rows).
- The kNN store is approximated by TF-IDF k-means clusters (k = 50) because no embedding model is available; the top-k (k = 5) majority readout is a diagnostic row only (the newest-record weights of thm:memory do not describe it, rem:accumulating-stores).
- W3 (LLM judge): X8's calibration ranks grok-4.6 best (AUROC 0.842) and deepseek-v4-pro poor (0.656). The 300-task W3 was run with deepseek-v4-pro (thinking off) per the coordinator's first instruction, before the grok result was known; a full grok W3 is unaffordable in ledger units (~150-230 units per call at the uncalibrated default rate, ~0.6M for 300 tasks x 8 models against a shared cap of 300k), so grok was run as a 2-cell pilot on the same pairs as deepseek (144 calls, 13.2k ledger units, 0 relay-error rows; the packy patch for the intermittent HTTP 400 'Incorrect API key' was in place and no row failed). The pilot is a judge comparison, not a claim pool: its populations are too small for out-of-sample primitives and are excluded from C1 / C2 / C5 (numbers reported separately).
- Empty recorded responses (data gap) are unverifiable: every verifier is imputed the released truth on them; counts are in `results.json` (`config.populations.*.stats`).
- The LRU prediction uses the realized coverage (no closed form for finite J); TTL / FIFO predictions use eq:ttl / eq:fifo with probing r_j.
- The replay mixes exploration rounds into every state's value and cost (as X4 did), so eta_U here is the efficiency of the exploring uninformed router, not of the pure prior.
- Streams are long (60,000 rounds) so that a FIFO of 5,000 write events fills; the 867-task population is therefore visited ~69 times per stream (the record process, not the task pool, is the object of study).
