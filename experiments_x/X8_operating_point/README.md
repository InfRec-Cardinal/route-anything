## Paper objects tested
* `H = 1{Sigma >= theta}`, `p = pi0 TPR + (1-pi0) FPR`, `p v_h = pi0 TPR` (main_body 'The verifier's operating point', app:operating-point).
* Floor eq:floor in operating-point form: `pi0 TPR(theta) b >= vbar a` -- false accepts do not enter (homogeneous case beta1 = beta0 = vbar). General affine form eq:app-operating-gain: `Q + eta_B S = pi0(1-beta1+vbar) TPR + (1-pi0)(vbar-beta0) FPR - vbar a/b`.
* Accepting everything (theta = 0) is efficiency-optimal over all operating points iff `a beta0 <= pi0 b` (general, constant b, Sigma _||_ Y_B | Y); homogeneous form `a/b <= pi0/vbar`; sufficient not necessary (uninformative score: `a/(a+b) <= pi0/vbar`).
* Quality floor `Q = pi0 (1-beta1) TPR - (1-pi0) beta0 FPR >= -eps` (eq:app-operating-Q) bounds FPR from above (eq:app-operating-fpr) and, for a score with a monotone likelihood ratio, theta from below: theta_min(eps).
* Premise `Sigma _||_ Y_B | Y` (conditional independence) tested directly; `e = (1-pi0) beta0 FPR`.

Judge tokens are also reported in ledger units (0.03088 units/token, the rate stored in `common/budget.json` for the judge model).
**Statistics.** eta = sum V / sum D (ratio of sums). ## Limitations
* id_test has only 334 runnable EXEC-CLEAN tasks; per-source cells on id_test are small (15-112 tasks), so many per-source realized CIs are wide and undecided.
* Truth is the released score; on humaneval/he/bcb the sandbox disagrees with it in 1-7% of rows (infra_smoke (b)), so V2 is near-oracle, not oracle; the oracle control uses the released score itself.
* V1 is neutral (0.5) on every mbpp task (no examples in the prompt) and structurally fails on most bcb doctests (multi-line or non-literal expected outputs), exactly as ACRouter's tool would; this is the imperfection being studied, not a bug.
* The dollar cost of the judge is a convention (primary's blended $/token); the seconds basis mixes recorded API latencies with sandbox wall time measured on this machine. The judge latency (mean 33-39 s, median 24 s per call) was measured under 4-10 concurrent calls on a shared relay, so V3's seconds basis is pessimistic; even at a quarter of that latency V3 would remain far below the reference in seconds (r about 0.1 at every theta).
* The judge calibration has 60 items (AUROC CI width about 0.2); the selected configuration is the best of five on that set, so its calibration AUROC is optimistically biased; the main-sample AUROC of V3 (table 9) is the unbiased figure.
* With a/b around 0.05 in dollars, accept-all is efficiency-optimal for every verifier in dollars; the seconds basis (where Opus is often the fastest model) supplies the discriminating cells for C2 and the negative-sign cells for C1.
