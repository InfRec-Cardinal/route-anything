# X12b_llm_signal — value of a pre-execution routing signal produced by an LLM (X12, LIVE part)

Theory objects tested (names as in the paper): eq:gate-costs, prop:voi / eq:band, eq:imperfect-voi, the perfect-information bound of app:imperfect-voi (`f(s) − E f(s_Z) ≤ f(s) − g(s) = min{s(b−a), a(1−s)}`), its "pays only if k < a" clause, its re-thresholding remark ("any monotone transform of s_Z used with the transformed threshold attains the bound"; the shrunken-score example), and cor:info-vs-proposer (`C_info − C_dec = bΔp − a(1−s)`). Definitions of f, g, the sufficiency event, realized cascade / direct / perfect-information costs, the uninformed choice, capture ratio and "decided" cells are copied from `../X12a_voi_released_signals/run.py` (which copied them from X3). Cost basis: dollars (csv `cost_usd` for a and b; the signal call priced at list prices, see below); tokens and seconds are used for the k < a condition.

Everything below is produced by `run.py` (seed 20260917). Files: `run.py`, `results.json` (all numbers with CIs, `claims`), `signal_rows.csv` (one row per sampled task: prompt length, the two LLM forecasts, labels, lines, tokens, latency, k in every price basis, the 8 released scores and costs), `signal_state_rows.csv` (one row per state × θ × primary × signal × usage), `band_rows.csv`, `info_vs_proposer_rows.csv` (exact-information form), `info_vs_proposer_actual_signal_rows.csv` (the actual signal at its measured k), `k_condition_rows.csv`, `signal_calls_{deepseek,qwen3max}_partial.jsonl` (raw replies, persisted every 100 tasks), `readme_tables.md` (machine-generated tables; the pooled, per-source, θ = 0.5, counterfactual and k-vs-a tables are reproduced there in full), `counterfactual_price_ratio_rows.csv`, `figures/fig1..fig7*.pdf`, `summary_for_paper.md`, `run_main.log` (the live run: 2,260 s from scratch, of which 2,226 s were the signal calls) and `run_cached_rerun.log` (the final code re-run from the cache: 36 s, 0 live calls, identical claims and audit).

## Setup

**Data (READ ONLY).** CodeRouterBench `id_results_long.csv` (9,999 tasks × 8 models; reference B = `claude-opus-4-6`); prompts reconstructed with `common.sources.load_task` (every sampled task resolved, no empty prompt). **Sources:** the EXEC-CLEAN sources humaneval, he, mbpp, bcb, hex (all five HumanEval-X languages, not only python — the truth is the released score, so a sandbox is not needed) plus lcb and ds1000 (prompts available; the verifier there is the release: private-test lcb agreement 0.73–0.92, ds1000 0.65 in `infra_smoke/report.md`). cruxeval is excluded (its prompt is "predict the output of f(input)", a task type for which a "difficulty / lines of code" forecast is ill-posed) and so are the non-exec sources. **All-zero exclusion (Addendum 2, applied to every source):** tasks whose released score is 0 for all 8 models are treated as ungraded and removed before sampling — bcb 750, ds1000 703, lcb 224, mbpp 281 (dim9 mbpp is entirely all-zero), he 16 — leaving a population of 3,601 tasks (2,547 probing / 1,054 id_test; `results.json → population`). A sensitivity of the probing sufficiency rate s with the all-zero tasks kept is stored in `signal_diagnostics.allzero_sensitivity_probing_population`. The 28 lcb tasks with empty recorded responses but released score 1 are kept (truth is the score; the gap concerns `response_matrix.json`, which this experiment never reads).

**Sample.** 600 probing + 600 id_test tasks, seed 20260917, stratified by source (water-filling over sources, then largest-remainder over dimension × source cells): probing {humaneval 67 (all), he 89, mbpp 88, bcb 89, hex 89, lcb 89, ds1000 89}, id_test {humaneval 33 (all), he 63 (all), mbpp 55 (all), bcb 115, hex 124, lcb 124, ds1000 86 (all)}. The qwen3-max second signal runs on a nested subsample of 200 + 200 tasks stratified by source (see Deviations: the relay's qwen3-max latency made the full sample infeasible inside the 2 h script limit).

**The signal Z (LIVE).** Before execution, `deepseek-v4-pro` (thinking disabled, `max_tokens` 200, temperature 0, 4 workers, every call cached in `common/cache`, tag `X12b`) reads the task prompt (middle-truncated at 5,000 characters; 0 of 1,200 prompts needed it) and returns ONE JSON object: `p_qwen3_max` and `p_kimi_k2_5` (its probability that Qwen3-Max / Kimi K2.5 produce a fully correct answer in one attempt, "passes every hidden test of the official harness"), `difficulty ∈ {easy, medium, hard}` and `expected_lines`. System prompt: "You are a senior software engineer who forecasts how likely specific AI coding models are to solve programming tasks. You never solve the task yourself; you only forecast. You answer with one JSON object and nothing else." The user turn names the two models (Qwen3-Max: Alibaba's flagship, non-reasoning; Kimi K2.5: Moonshot's open-weight MoE), asks for calibrated probabilities over the whole 0–1 range, lists what to consider (algorithmic difficulty, precision the hidden tests demand, completeness of the specification, code length) and pastes the task verbatim (`run.py → USER_TMPL`). Unparseable replies would be imputed (p = 0.5, medium, median lines) and flagged; none occurred. The same prompt goes to `qwen3-max` on the nested subsample (4 workers). **Variants of Z valued:** `llm_p` (the probability for the primary in question), `llm_label` (hard < medium < easy as a coarse ordinal Z; native rule = attempt unless "hard"), `llm_lines` (−expected_lines), `llm_p_shrunk` = p/10 (SEMI-SYNTHETIC, the paper's shrunken-score example), `llm_p_perm` (p permuted within dimension × source cell, SEMI-SYNTHETIC uninformative signal, 20 permutations), the qwen3-max family `qwen_p / qwen_label / qwen_lines / qwen_p_shrunk`, `llm_ensemble_mean` (mean of the two LLM probabilities), and — for like-for-like comparison on the same tasks — a TF-IDF logistic router trained on the 600 probing prompts (`tfidf_lr`: 1–2-grams, min_df 2, sublinear tf, C = 1, liblinear, 5-fold out-of-fold probabilities on probing for the calibrator, full fit applied to id_test; `tfidf_lr_uni`: unigrams, C = 0.3) and the ten released routers of X12-a (binary Z = "chose the primary" / "chose any non-Opus model", posteriors cross-fitted on id_test exactly as in X12-a because those files carry no probing decisions).

**Cost of the signal k.** Per task, the call's `prompt_tokens × input price + completion_tokens × output price`. deepseek-v4-pro: DeepSeek's time-of-day list prices in force since 2026-08-16 — peak $1.32 / $3.96 per M tokens (main, conservative), off-peak $0.66 / $1.98 (third-party trackers of the official page, see `run.py → PRICES`; the relay's own units are not a dollar price); qwen3-max: the CRB `models.json` list price $0.34 / $1.38 per M (and half of it as a low variant); a self-hosted router at the protocol's $0.054 per M tokens (X7 R1, X12-a `k_tok`) as the cheap benchmark. k is also reported in tokens (the call's total tokens vs the primary's mean `total_tokens`) and in seconds (call latency vs the primary's mean `latency_ms`). The ledger cost is `total_tokens × 0.00034 units` (calibrated rate for deepseek-v4-pro) and `× 0.05` (default) for qwen3-max.

**Truth and primitives.** Sufficiency H = 1{released score of the primary ≥ θ}, θ = 1 (main) and 0.5. Primaries m ∈ {Qwen3-Max, kimi-k2.5} (the two the LLM is asked about); the k < a condition and cor:info-vs-proposer use all seven non-Opus primaries. States x: the 7 sources, the 13 non-empty dimension × source cells, the 6 dimensions and the pooled set; states with fewer than 5 probing or 5 id_test tasks are skipped, states with fewer than 20 are flagged `small` and excluded from claim tests. Every primitive — s, a, b, a/b, the uninformed choice (cascade iff s > a/b), the bound `min{s(b−a), a(1−s)}`, and the calibrator — comes from the 600 probing tasks; every realized quantity from the 600 id_test tasks (OUT-OF-SAMPLE).

**Posterior s_Z and the two usages.** Isotonic regression of H on Z fitted on the pooled probing sample (one calibrator per θ, primary, signal), then anchored per state by the shift that makes the mean posterior on the state's probing tasks equal to s (so `E[s_Z] = s`, eq:imperfect-voi's premise; `anchor_shift` is stored). Two alternatives are stored for every row: the unanchored pooled posterior (`pooledcal`) and a per-state isotonic fit (`statecal`, states with ≥ 30 probing tasks and both classes). **Blackwell-optimal usage** = attempt iff s_Z > a/b. **Native usages** of a probability signal: the paper's rule "attempt iff p ≥ a/b" (`native_ab`), the router-style rule "attempt iff p ≥ 0.5" (`native_half`), and **re-thresholding** `rethr` = attempt iff p ≥ t*, t* the threshold minimising the probing cost of the rule (rank-preserving; the paper's "transformed threshold"). Realized cost per task `C_direct + attempt · (C_cascade − C_direct)`, gross VOI = realized mean cost of the uninformed choice − realized mean cost of the usage, net VOI = gross − k, capture = gross / bound (rows with bound ≤ 1e−9 are degenerate and excluded from ratios). Bootstrap: 1,000 paired task resamples per state (95 % percentile CIs); every pair of usages or signals is compared on the same resamples; task-weighted aggregates over the 7 source states sum the per-state replicate means (states are disjoint). Decision usefulness is also measured directly as the **switch share**, the fraction of id_test tasks on which the Blackwell rule deviates from the uninformed choice.

## Deviations from the protocol / integrator instructions

1. **qwen3-max on a 200 + 200 nested subsample, not the full 1,200.** The relay's qwen3-max latency during the run was bimodal (1.3–1.8 s or 60–110 s; mean 34 s at the 4-worker cap shared with X7-b and X8); 1,200 calls would have taken ≈ 2.8 h, so the second signal keeps the protocol's subsample size, doubled. The qwen3-max family and the deepseek signal restricted to the same tasks (`llm_p_sub`) are compared paired on those 400 tasks.
2. cruxeval (an EXEC-CLEAN-adjacent source) is excluded from the sample because its "predict the output" prompts do not admit a lines-of-code / difficulty forecast; hex is included with all five languages because the truth is the released score.
3. All-zero tasks are excluded in every source (the addendum names bcb); the mbpp dim9 cell disappears as a result.
4. The isotonic calibrator is fitted on the pooled probing sample and anchored per state (600 probing tasks cannot support a separate calibrator per cell); per-state calibrators are reported as a variant.
5. k for the deepseek signal is a list price (DeepSeek's own peak / off-peak schedule), not the relay's unit price; k for the released routers is 0 (no router tokens, as in X12-a) and for the TF-IDF router the prompt-token proxy of X12-a.
6. The LLM was asked with thinking disabled (a single forward pass); a reasoning forecast would cost 5–20× more tokens and was not budgeted.

**Why the TF-IDF router looks strong.** Its AUROC on hex is 0.98 / 0.94: the released HumanEval-X scores give partial credit 0.8 on most non-python tasks, so at θ = 1 the non-python languages are "insufficient" (s = 0.00 for cpp / go / js / java against 0.87 for python, `signal_diagnostics.hex_by_language_probing_population`) and a bag of words that recognises the language predicts H. At θ = 0.5 the hex state has s = 0.34 / 0.30 and the TF-IDF AUROC falls to 0.85 / 0.70 pooled. Source identity (prompt format) is the other lever. The LLM was not told the released grader's conventions.

## Hypothesis violations measured

* **E[s_Z] = s.** The pooled isotonic calibrator is far from state-calibrated: the per-state anchor shift is 0.215 in absolute value on average (max 0.49); after anchoring the posterior mean differs from the id_test s by 0.070 on average. Raw ECE 0.326 (state means) → 0.111 anchored, 0.255 un-anchored pooled. The un-anchored (`pooledcal`) and per-state (`statecal`) posteriors give Blackwell captures ≤ 0.50 / 0.79 of the bound and 0 violations.
* **Probing → id_test drift.** Mean |Δs| = 0.071, max 0.625 (cell code_completion|he for kimi, n = 26 / 32); the uninformed choice flips in-sample in 1 of 50 states.
* **0 < a < b task by task:** holds for 100 % of tasks for both primaries (the two cheapest models), so the pointwise dominance behind the bound is exact here.
* **Value preservation.** θ = 1: V_BW ≥ V_direct in every row, erroneous acceptance e = 0. θ = 0.5: V_BW < V_direct in 5.8 % of rows, mean e = 0.014; θ = 0.5 rows are outside the value-preserving premise and are reported for completeness (`readme_tables.md`).
* **Constant k.** k varies with prompt length (CV 0.27); the state mean enters net VOI. The deepseek price is a public list price at two time-of-day tiers; the relay's own units are not a dollar price.
* **Truth.** lcb (private tests; sandbox agreement 0.73–0.92) and ds1000 (0.65) rely on the released score; hex non-python scores are partial credit 0.8 (so θ = 1 makes "sufficiency" there a language indicator) and the dim9 test-generation scores are proxy scores. 28 lcb tasks have empty recorded responses but score 1; they are kept (the truth here is the score). All-zero tasks are excluded uniformly (bcb 750, ds1000 703, lcb 224, mbpp 281, he 16); with them kept the probing s of Qwen3-Max would fall from 0.67 to 0.21 (bcb), 0.38 to 0.11 (ds1000), 0.59 to 0.23 (mbpp) — the signal would be penalised for correctly calling those tasks solvable.
* **Signal-model conventions.** Thinking disabled (a single forward pass); the forecasts collapse to 20 distinct values and 88 % "easy"; the two primaries receive rank-identical forecasts (Spearman 0.999). qwen3-max's forecast agrees with deepseek's at Spearman 0.69–0.73 and on the difficulty label 46 % of the time.

## Limitations

* 600 + 600 tasks: per-source states have 89 / 33–124 tasks and the fine-tuned routers' and TF-IDF's advantage over the LLM is CI-decided only for Qwen3-Max; the qwen3-max second signal lives on 200 + 200 tasks (relay latency), so its per-source rows have n ≈ 28 and only hex is decided.
* Capture is a step function of whether the posterior crosses a/b; at price ratios of 2–10 % it is identically 0 wherever s ≥ 0.4, whatever the signal's AUROC. The counterfactual sweep shows that the LLM's ranking would not become valuable at higher ratios either, but that check is SEMI-SYNTHETIC.
* The LLM was queried once, without reasoning, with one prompt; a reasoning forecast (5–20 × the tokens, i.e. 15–60 × a Qwen3-Max attempt) or few-shot conditioning on the released grader's conventions might discriminate better. The TF-IDF router's advantage is partly an artefact of the released grader (partial credit on non-python HumanEval-X; source formatting).
* The dollar price of k is a list price at DeepSeek's two time-of-day tiers; the relay's unit price is unknown for qwen3-max (ledger uses the 0.05 default). The released routers' k is 0 (no router tokens in the files).
* θ = 0.5 rows violate the value-preserving premise; latency and token bases are used only for the k < a condition; the 21-cell partition is reduced to 13 non-empty executable cells here.
